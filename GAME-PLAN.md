## Player and delivery contract

A quiet, tactile mahjong solitaire game: select two identical free tiles until the board is empty. A tile is free when no tile covers it and at least one horizontal side is open on its own layer. Exact symbols match, including flowers and seasons (no wildcard groups). A run takes approximately 2–10 minutes; there is no time limit or loss penalty. The elapsed clock pauses while hidden or a dialog is open. Dead ends offer undo, restart and an unlimited solvable reshuffle. Hints are unlimited; using one prevents the third star for that attempt. Stars recognize completion (one), no reshuffle (two), and neither reshuffle nor hint (three); undo is unrestricted and does not refund hint or reshuffle use.

Deliver 60 individually identified levels in six ten-level chapters; 60 unique geometries vary in size, stacking and tile variety across six chapters. All levels are available from entry. Persist completion, best stars, settings, an exact active-run checkpoint and studio drafts. Traditional, animal and emoji faces can switch during a run without changing matching identities. Traditional artwork is original SVG, with named suits and ranks; no font dependency.

Visual direction, approved MG-019: an atmospheric illustrated puzzle game with six original chapter environments, a dedicated title screen and full-window play. Native CSS 3D tiles use front, back and side planes, ivory bevels, jade backs, shallow board perspective and a lifted selected state. Match faces remain interchangeable, including personal photos. Collections and studio live in game menus; paper-toned native dialogs remain readable over the scenery. Serif display type with a system sans interface. Avoid colored card accent rails and northeast arrow icons. Preserve native keyboard controls, clearly selected and blocked states, reduced motion and default-on synthesized music/effects after an eligible interaction, separate volume/mute controls and a level-clear celebration. `audit/presentation/PLAN.md` is the authoritative acceptance inventory for the added presentation outcomes.

## Content, authority and editing

`content/levels.html` is the sole authored campaign definition. Each semantic level article has a permanent ID, revision, name, chapter, teaching goal and a list of coordinate-bearing tile positions. A one-time authoring generator creates that reviewable source; build does not silently regenerate or replace it. Runtime derives read-only numeric coordinates from validated HTML. The gameplay state owns accepted removals and assignments, separate from authored positions. Rules revision is `mg-rules-1`, content revision `1`, save format `1`, release version separate.

Studio: add/remove cells on a keyboard-accessible layered grid, choose layer, name the layout, undo/redo, validate and playtest. Editable authority is the studio DOM tile list; controls operate on that root. Save/export serializes current DOM fields. Layouts support 8 columns × 6 rows × 3 layers (144 positions maximum), unique integer coordinates and at least four/even tile counts. Validate removable geometry with a bounded 30,000-node search; a rejected edit/import retains the previous draft. A cell on a higher layer must have a supporting tile immediately below. Export/import one versioned JSON interchange envelope containing a strict reconstruction of the allowed HTML fields and optional image data; JSON is transport, not a competing editable domain definition. Reject unknown fields and future versions before mutation.

Custom tile set: 2–36 user-selected PNG/JPEG/WebP files, 5 MB input maximum each, verify the file header and a 16 megapixel input bound before a cancellable, timed decode, then resize to at most 160 × 160 and re-encode as PNG. No SVG/HTML or remote URLs. Stored embedded images are limited to 250 KB each and 8 MB aggregate, with fallback labels and unique IDs. Matching uses stable face IDs, never image pixels. Images are local to this browser; export is explicit. Built-in sets never need uploads. Replacing images changes the visual set only; active-run matching IDs stay intact.

## Rules, recovery and storage

Pure validated commands operate on immutable run snapshots: select/deselect, match, undo, hint, reshuffle, restart and complete. Legal matches remove exactly two tiles once; animations are decorative. Seeded pair placement follows an executable legal removal path so every new campaign/custom deal is solvable. Solvability of arbitrary choices is not promised. Reshuffle preserves remaining geometry/count and may restore a tile face assignment from a new legal path; if remaining geometry cannot be paired, undo/restart remains available. A bounded solver returns success, impossible or budget reached distinctly.

IndexedDB stores the version1 game profile and a separate version1 audio mixer record with revision checks. The mixer is the sole current audio authority; the old sound flag remains compatibility data. Profile/mixer writes are one atomic transaction. New portable backup envelope2 includes both; legacy envelope1 imports retain the current mixer. Serialize transactions, refuse cross-tab stale writes, keep working state on quota/denial, show a recoverable error and provide export/retry. Restore into a separate validated candidate and commit only when every field and referenced layout has passed. Malformed/future saves remain untouched; offer fresh temporary play and data export. Preserve the last valid revision on failure. Settings, run, progress and editor share one local transaction to avoid partial restoration. No accounts or telemetry. Game files are static; explicit leaderboard submission writes only the native shared score resource under its public schema/grammar controls. Owner WebDAV remains trusted authoring and bypasses those application controls.

## Inputs, layout, accessibility and budgets

Native mouse/keyboard/assistive click and independent touch/pen release dispatch the same validated selection command. Surviving tile buttons and visible face nodes stay connected through selection and matching. Touch ownership, movement/cancellation, compatibility-click deduplication and exact evidence are specified in `audit/touch/PLAN.md`. Arrow keys move tile focus spatially; H hints, U undoes, Escape deselects; shortcuts ignore text fields and dialogs. Tab visits every native control. Dialogs trap focus through native modal behavior and return it to the opener. Essential gameplay has an alternative compact accessible tile list. Menus target 44 CSS pixels, board source widths at least 48 CSS pixels (measured rendered bounds exceed 44 pixels in accepted fixtures); a size control permits larger tiles with scrollable spatial play. Surrounding UI reflows at 320 CSS pixels and 200% text enlargement; portrait and landscape remain usable. Honor safe insets and normal page zoom.

Target: current Chromium desktop, responsive layouts at 320×568, 390×844, 844×390, 1280×720 and 1440×900, pointer and keyboard. Actual available browser/version evidence will be named. Other engines/physical phones remain unverified, not claimed certified. WCAG AA is an engineering target, not a conformance claim. Meaningful labels, focus, selection text, live status, no color-only matching, no flashing, reduced motion. Music/effects default on at first mixer launch (35%/65%); explicit later mute/volume preferences persist. Optional audio starts after an eligible interaction, continues across menus, and pauses/cancels when hidden, leaving or transitioning. Effects include ordinary matches and a distinct celebration only for a newly completed player match. Audio failure shows retry and does not block play. `audit/audio/PLAN.md` owns the added requirements and evidence boundary.

Performance goals: dependency-free production JS, under 400,000 bytes initial code/content including scenery and CSS but excluding imported images, board actions under 100 ms on the observed desktop, no continuous graphics animation or simulation loop. Active music uses a bounded100ms audio-clock scheduler with180ms lookahead and20-voice cap; muted music schedules nothing. Stylesheets remain canonical source files; the build freezes their bytes into the entry document for deterministic first paint and counts those bytes once. Immutable stylesheet copies are retained as non-initial artifacts. Bound tile counts, imports, searches, DOM work and retained histories. Retain measured timings and explain tool limits.
