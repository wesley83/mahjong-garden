## Coverage decision

The new points derive solely from completion, original pair count and cumulative hint/reshuffle counters. They do not award repeated match events, refund help on Undo, or use time for rank. Original size normalizes how much a hint reveals; each whole reshuffle has an explicit2000 cost. Completion retains1000 minimum; clean clears10000; equal points share competition rank. Progress stars remain compatible. These weights are a declared design judgement for a relaxed puzzle and are not an enjoyment/competitive-authenticity claim. Different levels have separate boards. The UI explains the costs, repeated still-highlighted hint costs nothing, and failed assistance has no extra charge.

Shared results use an independent V2 semantic document and scoring identity. V1 records remain untouched/readable in a visibly separate, read-only Previous scoring view; a frozen legacy pending payload still retries its V1 endpoint. Server policy derives official pair counts from canonical campaign HTML and checks exact arithmetic/stars, schema and stable duplicate identity. No account identity, honest-play proof, profanity moderation or aggregate server quota is implied. Existing editor/photo/game/run/audio/backup fields were not migrated or overwritten.

The PWA manifest/icons and actual root-scoped worker are present. The worker has no cache or fetch transformation, and skipWaiting is requested only after explicit acceptance. Client discovery checks the served root identity, not a staged worker/version marker; a waiting script alone does not announce an unpublished game. Visible/manual/foreground/online checks are bounded; hidden pages do not poll. A new release announces itself in the game and Settings. Later preserves play. Before acceptance the app durably snapshots its game/audio/live studio DOM and refuses temporary/recovery/busy/failed-save states. Successful save releases contacts/audio and makes the old body inert during activation/reload. Another tab's controller change cannot force reload without this client's accepted flag. Cache-busted navigation fetches the newly served entry. A registration failure leaves ordinary online version discovery usable; initial publication promotes root before mutable manifest/worker controls, so a client in that brief staging window can use this fallback and acquire registration on a later reload. No closed-app push, OS notification permission or offline play is claimed.

Presentation refinement: runtime fingerprints remain in diagnostic/evidence records; player-facing update text uses plain language. The notification and safe explicit acceptance outcomes are unchanged. Build additionally omits only optional </li> end tags in its generated campaign copy, with complete parsed-campaign equality required before output and in tests. Canonical authored HTML remains unchanged/readable. This preserves the400000-byte initial budget while including startup updater/scoring code, root manifest/worker and game content.

Coverage decision: adopted outcomes implemented. Public promotion/real-host installation checks remain separate final work; an already-open1.4 client cannot acquire an updater without its first refresh/reopen.
